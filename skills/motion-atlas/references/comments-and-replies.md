# Comments and replies

## Find examples

Search the Comments and replies taxonomy by voice, humor pattern, video subject, platform, or thread format. Read the actual stored example packets. Planned entries contain no proven winning reply. Use `templates/comment-study.json` when adding examples.

## Understand the situation

Read or view the actual video and relevant moment. Read the parent comment when replying inside a thread. Ask for missing content only if it cannot be retrieved and the missing context matters. Identify the audience, language, tone, and whether the moment calls for humor, help, support, or a serious response.

## Draft

Choose an observable detail from the video. Select a compatible voice: casual Gen Z, deadpan, absurdist, literal wordplay, witty brand, warm brand, expert, thoughtful, or supportive. Match a brand’s supplied voice notes. Make the response sound like something a person would actually post. Prefer a clear specific observation or callback. Avoid forcing slang, repeating stock lines, inventing a personal experience, or claiming to represent a brand without that context.

Draft a few distinct candidates when requested and rank them by fit, specificity, naturalness, brevity, and strength of the joke or contribution. Explain a choice briefly if useful. Drafting a comment does not authorize posting it.

## Record evidence

Store original video/source, timestamp, parent comment, reply text, screenshot, voice, and analysis together. Record real likes, replies, pinned status, and dates only when supplied or observed. High observed engagement does not by itself identify the cause or predict a new reply’s performance. Never invent engagement numbers or describe checklist prompts as successful tested examples.

## Use browser backups

Device-local uploads are included in full library backups. Use the repository’s unpacker to restore media and entry metadata before inspecting examples.
